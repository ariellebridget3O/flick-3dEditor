## Recurring operational know-how
1. **Minified names reshuffle per build** — port VALUES/data-shapes, never names. Locate subsystems by signature strings ("cam-move", 1.299, PlaneGeometry(80000...), GC regex shapes).
2. **Analysis docs can MIS-TRANSCRIBE** — always re-verify a formula against the raw bundle bytes before porting (round-2 examples: mT sqrt metric, floor polygonOffsetFactor 4, pan_sweep anchor). The audit agents found these by re-reading raw, not the docs.
3. **y2r vs KCe**: same cam-move family, OPPOSITE directions — KCe is the forward eval (start→end), y2r the rebase inverse (end→start). Signs intentionally flip; don't "fix" one to match the other.
4. **Baked vs computed state**: saved scenes carry anchor in/out tangents (eval uses as-is); painting/editing recomputes via buildTangents. Test tangent math by APPENDING anchors, not by reading fixtures.
5. **Rendering-path architecture** (flick "look"): plain render OR finish composer (hKt: MSAA HalfFloat RT + depth texture → half-res RedFormat SSAO ping-pong → composite w/ occlusion tint + crease edges + dither + gl_FragDepth) — chosen by `finishOn()` = capability && localStorage pref (auto-measured, ≤11ms @1080p). Stroke ring shares the SAME predicate. ALL props are clay (one shared #e2e0dc rough-1 material — FNr strips GLB materials). Planning-aids pass has NO clearDepth (aids occlude behind geometry).
6. **ES-module cache in headless Chrome**: reload does NOT refetch — `agent-browser close` + open with fresh `?v=N`. Serve with `python3 -m http.server`.
7. **three r182 pitfalls**: TransformControls not an Object3D (`getHelper()`); PCFSoftShadowMap deprecated → PCFShadowMap; custom ShaderMaterials need `fog:false` under FogExp2; `THREE.Ray` has no intersectObjects; vendor three.core.js + three.module.js + GLTFLoader needs utils/BufferGeometryUtils.js; r182 WebGLRenderTarget supports `samples` + depthTexture (the finish composer relies on both).
8. **Layout-track wrappers** `{item, startS, endS}` — every consumer must unwrap (`u.item`).
9. **Bash pipelines eat literal `[h`** in OUTPUT display (sed/grep) — files are fine; verify with Read. Same class of gotcha: sub-agent dumps sanitize `[`→`【】`.
10. **VLM QA loop**: screenshot → sub-agent visual check with explicit expected-content list → verdict + nits. Catches real bugs; but VERIFY pixel-level claims programmatically when a "FAIL" is surprising (round-2: VLM called the lantern glow missing — pixel scan at the mathematically projected position proved it rendered).
11. **Watchdog** force-checkouts /home/z/my-project only — /home/z/flick-3dEditor is safe. /home/sync as third backup (background rsync for 100MB+).
12. **GitLab WAF** 403 ~1/3 of pushes — retry loop in background (`nohup for i in 1..5; sleep 15; git push ...`); GH is primary.
13. **Edit-tool discipline**: long old_str blocks fail on invisible whitespace — use short anchors or python `replace` scripts with `assert old in s` (guarantees the match, fails loudly).
14. **Commit-pipeline testing without a mouse**: set `manip._attached`, `manip.dragging`, `manip._dragStartObj`, `app.show.beginEditGesture()`, mutate mesh/store, call `manip._commit()`, then inspect store + read the undo round-trip. Remember `addItem` PACKS items (sequential bumping) — the playhead must be sought INSIDE the packed startS, not the requested one.
15. **Undo parity**: the gesture snapshot must cover objects+show (setUndoCompanion) and endEditGesture must run AFTER the commit writes — otherwise drags aren't undoable.

## Round-4 additions
29. **Synthetic PointerEvents need `pointerType:'mouse'`** for anything that switches on pointerType (stock TransformControls onPointerHover) — default '' falls through silently; also stock vendor setPointerCapture is NOT try/catch'd, so use agent-browser NATIVE `mouse` commands for vendor-control drags (synthetic pointerIds throw NotFoundError).
30. **A reload does NOT bust the ES-module cache** even with a bumped ?v= on the page URL (import URLs are unversioned) — close the browser session and reopen. Symptom: error stack line numbers that don't match the current file.
31. **In-place DOM updates for capture-holding overlays** — a React-equivalent re-render via innerHTML destroys the element holding pointer capture mid-drag. Update styles/classes on persistent elements; only rebuild elements that never hold capture (guides/ghosts).
32. **Interaction-flag discipline**: every early return inside a gesture must still be reachable for cleanup — the round-4 P0 was `addEventListener('pointerup', undefined)` (a silent no-op) leaving `app._tl.interaction='trim'` set forever: no undo push AND refreshTimeline permanently suppressed. Use ONE `finish` listener for up+cancel and reference only names that exist in scope.
33. **Live setHex-override tricks are for THEIR codebase** — the live f8 material intercepts `color.setHex` to force the hover color, but stock r182 highlights via `color.copy(materialLib.active.color)`; the equivalent is `tc.setColors(x, y, z, hoverColor)`. Port the OBSERVABLE, not the mechanism.
34. **Decode i18n keys as unavailable** — the message catalog is a separate compiled asset, not in the JS bundle; use semantic English strings and note them as equivalents (never invent "exact" wording).
35. **Sandbox policy drifts between sessions** — `ln -s` and bind mounts worked in round 3, blocked in round 4. Detection: tool errors on previously-working commands; fallback = rsync copy + sync script.

## Round-5 additions
36. **three's PropertyMixer skips no-change writes** (accu0 vs accu1 comparison) — any "restore-to-bind then let mixer write" scheme breaks when the sampled pose is static (idle@t=0 during gaps): the mixer skips, the restore wins, you get bind-pose flashes. The live's answer: never restore to BIND — restore to the last PRE-OFFSET pose (dynamic clipLocal), so even a skipped write leaves the correct pose.
37. **Analysis docs AND self-derived specs can mis-transcribe** — round-5 had two: cookie bucket (n=round(d/100×Eat), NOT scaled to texture px) and playback timeS (PINNED clipTimeS, NOT null — only livePlay passes null). Always re-read the raw bundle bytes at the cited offset before porting a constant that "looks wrong".
38. **/home/sync working trees go stale mid-round** — its .git has every commit but the checked-out tree can be an hour old. After ANY restore: `git log -1` AND `git status`; if dirty or behind, `git reset --hard HEAD`. Editing a stale tree produces a commit that silently deletes later rounds (the a55a900 incident).
39. **Gesture brackets for object ops** belong at the UI event level (one begin/end pair per user gesture); the show store's depth-counter makes nesting safe (manipulator drag brackets outermost, _commit self-brackets inner).
40. **Same-value state changes need an event, not a value diff** — a seek to the current playhead must still pose the scene (live performanceSeekS transitions null→t). Emit an epoch counter in the store action; never detect "change" by comparing the value.


## Round-6 additions
41. **Port inventions create the user's complaints** — the "clip dropdown that does nothing" was OUR invention (live has no clip dropdown in the object inspector); the "no-op +" was a missing import throwing silently; the "thick axis line" was stock vendor code the live rewrite never shipped. When the user reports something "broken", FIRST ask: does the live bundle even have this? (R2/R3 pattern: verify against bundle + DOM_REFERENCE before designing).
42. **Analysis docs can be wrong about OUR OWN prior work too** — EDITOR_UX §2.7 "group delete re-parents children" was wrong (bundle recurses); ROUND5_UI_SWEEP_A even documented the wrong behavior as WORKS. The divergence registry (AUDIT_*.md) outranks prose docs; when a doc and the bundle disagree, the bundle wins and the doc must be corrected.
43. **Silent throw = perceived no-op** — a missing import (appendPlace) made every lane-add menu click throw inside an onclick (menu closed, nothing happened). Any "button does nothing" report: check the console for per-click exceptions BEFORE redesigning UX.
44. **MultiEdit is not atomic in practice** — a failed edit can leave earlier edits applied (env.js fogK double-declaration). After ANY failed MultiEdit: node --check + grep for duplicated identifiers. Prefer python assert-scripts (assert old in s fails loudly).
45. **Per-frame values need frame waits in E2E** — fog density, undoStack depth, rotateHandlePx, matrixWorld all update on the NEXT rAF. Same-eval reads see stale state → sleep 0.3-0.6s between mutate and read (this false-negatived three round-6 verifications before the waits were added).
46. **THREE scratch objects must be real** — getWorldPosition/getWorldDirection require .set/.copy (plain objects throw "target.setFromMatrixPosition is not a function"). When THREE isn't in scope, read matrixWorld.elements directly ([12..14] position, [8..10] forward).
47. **Daylight-table architecture is the right extension point** — new lighting features (weather/geo/indoor) should multiply/derive the EXISTING byte-exact DAYLIGHT_STOPS outputs (pre-table inputs → az/el interface → table), never replace the table. The fog multiplier lives INSIDE createFogNearFar (post-hoc density writes get stomped every tick).
48. **Plan-view direction convention**: forward = (−sin yaw, −cos yaw) in plan coords (x east right, +z down-screen); screen-up is world −Z. Live FU. Getting this backwards points wedges/facing/pools the wrong way (round-6 review P1-2) — the same convention serves 3D (manipulate.js "camera faces −Z") and the plan.

## Round-8 additions
56. **Registration order IS dispatch order for same-element listeners** — a recovery/cleanup guard registered after the main handler runs after it and releases exactly what the handler just opened (silent dead-drag). Register guards FIRST; make the guarded action idempotent so the guard-before-main ordering is safe.
57. **Verbatim units ≠ self-verification** — the addClipItem/addCameraItem/LHr store methods had NO extracted units (only MAP prose) and shipped fine, but the reviewer flagged them as the only MAP-inferred parts. When a family has no verbatim unit, dump one BEFORE porting (the r8b pass did this for aim-math and caught the guard semantics that prose had wrong: "any prior Fp item startS<s && !cam-still aborts").
58. **Transport limits in tooling**: agent-browser eval chokes >~1.5KB — persist long probes to files and `$(cat)`. MultiEdit-style asserts fail on the FIRST mismatch silently leaving later edits unapplied — always re-`node --check` after every patch script (SKILL #44 pattern, hit again).
59. **HTML5 DnD is E2E-able**: synthetic DragEvent + one shared `new DataTransfer()` (set on dragstart, defineProperty per event) works in Chromium; dropEffect readback is browser-normalized and unreliable — assert glow/store effects instead. dataTransfer.types.includes(MIME) gates work in dragover handlers.
60. **maxEnd(items) expects ITEMS not intervals** — maxEnd over {startS,endS} objects yields NaN (itemDuration reads .durationS). Verbatim MP reduces endS directly. Watch argument-shape when reusing ported helpers (place.js maxEnd vs bundle MP are shape-different on purpose).
61. **class-field arrow `drawPose` on lazily-created renderers**: still-pose redraws after a hover loop must re-run the SAME path as mount-time stills (pointerleave → stopLoop + draw) or tiles keep the last animation frame (live redraws in onPointerLeave — P5r/O5r/R5r).
62. **clone(true) shares GEOMETRY, not just materials** — per-instance GLB clones need geometry.clone() alongside material.clone() or any dispose() walk kills sibling buffers (three re-uploads on next render, so it degrades quietly).
63. **"React memo panel" ports → subscribe+render-on-open, NOT render-on-every-store-change** — the palette renders on open/tab/search/selectedId-change only; add-button enable states update via a cheap DOM pass on objects changes; the curve panel updates ONLY the playhead line per frame. Full innerHTML rebuilds at 60fps were the biggest perf smell the review caught.

## Round-7 additions
49. **"Exact port" requires function-level extraction, not spec-notes** — the round-6 plan canvas was built from digested research and diverged in 14 places (2 of them user-visible bugs: mirrored rotate handle, 2× figure footprint). The working method: extract VERBATIM function bodies from the bundle (scripts/r7_plan_extract.py pattern: signature anchors + brace-matching + node --check per unit), build the DIFF TABLE first, then port 1:1 with the same names/math. Keep the extraction dir (analysis/tmp_plan_exact/) as the permanent registry.
50. **Oracle = run the bundle's own code as the reference** — assemble the verbatim fns into a runnable module (shims for three classes + tiny helpers, all byte-verified against the raw bundle at their offsets) and diff against the port at 1e-4 with ORDERED draw-call streams for painters (order is the spec) and intent-sequence diffs for reducers. This catches what E2E can't (portrait-aspect fov clamps, edge-indicator clamp math). CAUTION: an oracle that silently compares the port against ITSELF is worse than no oracle — assert the reference export exists and FAIL LOUDLY (round-7 T8 was vacuous until review caught it).
51. **The watchdog rewrites .git/config inside /home/z/my-project** (~2min after any edit — host-level snapshot revert, verified twice). Never rely on named remotes there; always push with FULL PAT URLs. Detection: `git remote -v` right before pushing.
52. **Bundle class-field arrows (e.g. replaceMoveFromSamples=(e,n,r,s)=>...) can't be .call()-bound** after extraction — convert the head to a `function` expression when assembling the oracle reference; bare free identifiers inside them (an()) need module-level shims.
53. **setPointerCapture throws on synthetic pointerIds BEFORE the handler body runs** (hit again after a full rewrite — the guard is the FIRST thing to check when a brand-new pointer flow "does nothing" in E2E). Guard with try/catch; real-pointer behavior unchanged.
54. **setShow/setObjects wipe the undo stack** — any destructive reset (New empty scene) must be gesture-bracketed BEFORE the wipe to stay undoable; one-click resets without this are unrecoverable data loss (review P2).
55. **User-provided names flow into innerHTML in shared-scene contexts** — build pills/labels with createElement+textContent or escape; scene files are a sharing currency (R7-2 library), so name injection is a real vector, not theoretical.

## Round-10 additions
67. **three r182 readRenderTargetPixels on HalfFloat RTs reads type HALF_FLOAT** — the buffer must be Uint16Array (raw half bits), decoded manually ((1+f/1024)*2^(e-15), subnormals (f/1024)*2^-14); a Float32Array buffer silently stays zero and looks like a black-bake bug.
68. **Framebuffer-feedback loops are prevented by compile-time sampler omission, not runtime binding discipline** — per-pass #ifdef'd sampler declarations (the reference's transmittance pass binds no textures at all) make the hazard structurally impossible; shared uniform objects with "unused" textures still form loops via default texture units.
69. **Bake/read parametrization pairs must be E2E-diffed against each other, not just smoke-tested** — the sky-view LUT baked vertically flipped for a full round because the bake and the read were each individually plausible and the visual ("zenith brighter than horizon") got rationalized; the reviewer's fix was to re-bake the LUT in double precision OFF the GPU and compare. An independent implementation of the same math is the only real orientation check.
70. **Screenshot gates need a scene-load marker** — mutating app state (light/camera) while `await loadSceneData` is still in flight gets silently overwritten; poll a post-load invariant first (e.g. light === scene default && rigs loaded). Likewise ?finish=0/1 persists localStorage across sessions.
71. **VLM QA "false positives" can hide real bugs** — the VLM's "the moon is just the nav gizmo" verdict exposed a field-name mismatch (nightAmt vs nightAmount) that numeric star-pixel counting had mis-attributed to the gizmo; when a VLM FAIL contradicts a pixel count, re-derive both.

## Round-12 additions
83. **The compositor can FREEZE while the renderer still runs**: under headless SwiftShader, Chrome's present path for a WebGL canvas stopped updating once the cameras view activated — the frame counter incremented, the forced-render backbuffer held the correct image, and the page screenshot returned the same stale frame for 40+ minutes (byte-identical across sessions; resize/transform/DOM pokes didn't unstick). Diagnosis pattern when state and pixels disagree: (1) hook renderer.render to log the camera actually passed, (2) readPixels the backbuffer right after a forced render IN THE SAME TASK (preserveDrawingBuffer=false means the buffer only survives that task), (3) compare the backbuffer with the screenshot. Capture WebGL content from the BACKBUFFER, never the composited page.
84. **A renderer-side effect can be validated empirically by REMOVING it at runtime**: the fog ramp mystery fell to a fog-zeroing probe (disable the per-frame writer fogNearFar.tick FIRST — the tick rewrites state every frame and silently undoes the mutation — then zero the density, capture, diff). The per-channel shape of (with − without) then identifies the term precisely (uniform = factor; non-uniform per channel = a color difference); the residual over a validated model isolates whatever the other side adds.
85. **Non-constant implied-parameter fits = the model, not the constant, is wrong**: solving ρ row-by-row from an image (ρ_i = √(−ln(1−f))/z) must give a constant; when it drifts 2×, the depth metric (view-z vs euclidean) or the model itself is wrong. Re-derive from first principles (three's fog chunk: vFogDepth = −mvPosition.z) before fitting more.
86. **Bundle redeploys invalidate offsets, not knowledge**: the site serves a new bundle with every name reshuffled — but signature strings (table values like 9677260, constant tuples like =-8,, shader snippets) locate the same code instantly. Re-verify the subsystem byte-for-byte in the NEW bundle before assuming it changed; re-fetch and KEEP the deployed bundle in analysis/ as the current reference.


## Round-13 additions
87. **Sub-agents can and DO implement beyond their stated mandate** — twice this round an agent shipped full E2E-verified commits while its final message claimed "no files touched" (the draw-path audit agent landed the fixes; a clouds implementation appeared mid-audit). ALWAYS `git log --oneline -5` + `git status` after ANY sub-agent returns, before crediting, duplicating, or re-doing work — the git history is the truth, the agent's self-report is not.
88. **agent-browser evals silently FAIL under heavy GPU load**: when the page renders ~250ms+ frames (SwiftShader + heavy shaders), evals can return a bare `{}` WITHOUT EXECUTING any of their statements — side-effecting evals (setWeather/setSkyStyle) appear to "revert" later. Never trust a `{}` display; batch mutation+assertion in ONE eval; verify state after every mutation eval; a "revert" is usually a never-ran.
89. **In-session shader mutation debugging is stateful poison**: patching material.fragmentShader via eval (replace + needsUpdate) leaves the corrupted material for EVERY subsequent test in the session — "the feature renders nothing" conclusions from late-session tests are artifacts of your own earlier debug mutations. One hypothesis per fresh page load (?v= bump); the page screenshot is ALSO stale (see #83) — the backbuffer readPixels capture is the only truth.
90. **QA-harness geometry drifts invalidate verdicts, not just pixels**: a tune harness's "sky-aimed" camera was silently pointing at the FLOOR (position/target edit lost the up-tilt) — an entire session's captures were the ground plane while commit messages claimed sky QA, and the next round's VLM then REJECTed the feature as "flat pale wash" (it was measuring the fog-drowned floor). Before acting on ANY whole-feature visual verdict: Read one capture YOURSELF and confirm the camera is looking at the subject (harness asserts on canvas-rect size do not cover pose). Symmetric lesson: a VLM's pixel forensics were exactly right (flat 0.87 luma) — the bug was in the harness, not the renderer.


## Round-14 additions
91. **When a lighting knob fails to move a metric, measure WHERE the pixel's energy comes from before tuning further** — the clouds "flat bright deck" survived 3 lighting iterations because the premultiplied over-composite was displaying 20-85% bright SKY through an optically-thin veil (Tview never dropped below ~0.5); no amount of light-march/ambient tuning can fix a transparency problem. The diagnostic that unlocked it: computing the achievable tau (SIGMA_K x rho x path) and finding the ceiling — the model's structure, not its constants, was wrong. Same class as SKILL #85 (the model, not the constant).
92. **Test assertions carry their own assumptions — an E2E "failure" that a direct probe contradicts means the ASSERTION is wrong before the code is** — `transform.object === null` failed forever while every debug read showed the detach working: three r182's TransformControls detach() sets object = UNDEFINED. Cost ~1h against a feature that was already correct. When a repro won't reproduce inside a bigger suite, test the assertion's literals against the vendor source first. ## Round-15 additions
93. **Oracle/E2E dual-side comparisons must feed IDENTICAL inputs and complete probe magnitudes** — two r15 failures were HARNESS bugs wearing feature-bug costumes: (1) a cL matrix built the reference and port cameras from separate random draws (comparing noise against noise — 20 "failures" vanished with one shared pose spec); (2) a pixel probe sliced its own output to the top rows, so a huge frame shift read as "identical". When a comparison verdict surprises you, dump the raw inputs/outputs and diff them by hand before touching the implementation (extends SKILL #50: non-vacuous is not enough — the harness must be identical-input AND full-observation).

## Round-17 additions
96. **An oracle over PRIMITIVES does not certify the COMPOSITION** — the r17 drive oracle ran 2501 checks over every spring/stick/pan/move/roll unit (all exact) plus an "80-frame trajectory" whose driver was my own hand-transcription of en on BOTH sides; the P0 (a mistranscribed yaw-spring target that killed mouse-look on every rig) lived in exactly that glue and passed vacuously — only the code review caught it, and the fix needed a NEW E2E case (rotate the aim, assert the cam follows).
